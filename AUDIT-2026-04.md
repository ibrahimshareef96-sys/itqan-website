# Itqan Website — Audit vs won.agency reference

**Date:** 2026-04-15
**Reference:** https://won.agency
**Auditor:** Claude (AI-assisted competitive analysis)
**Scope:** 12-dimension audit across homepage, services, work, about, contact, and case studies

---

## Executive summary

Itqan's website has solid technical foundations — clean Next.js architecture, a well-organized animation system, and consistent brand colors — but it reads like a **competent portfolio site**, not a **premium agency site that closes deals**. Won.agency succeeds through copy discipline (short, confident, outcome-oriented), strategic restraint (fewer words, more white space, no filler sections), and a conversion architecture that makes "Book a discovery call" feel inevitable rather than pushy. Itqan's primary gaps are: (1) copy that describes process instead of promising outcomes, (2) too many sections that dilute rather than build momentum, (3) zero quantified results anywhere on the site, and (4) a contact page with high friction and generic CTA language. Closing these gaps does not require a visual rebrand — Itqan's mauve/espresso palette and Playfair editorial voice are strong foundations — but it does require rewriting nearly every headline and restructuring the page flow.

## Design gap — specific weaknesses

### 1. Homepage section density
Itqan has 10 sections on the homepage (Hero, Brand Statement, Social Proof logos, Testimonial, Services, Process, Benefits, Portfolio, CTA, FAQ). Won has ~5 (Hero, Metric, Services, Featured Work, CTA). **Every extra section dilutes the page's momentum.** The Benefits comparison ("With Itqan" vs "Without Itqan") is particularly damaging — it's a template pattern that signals insecurity rather than confidence.

### 2. Service cards lack hierarchy
Itqan shows 4 service cards at equal visual weight with identical layouts. Won differentiates services through varied imagery and copy length. **Fix:** Give Brand Identity visual priority (it's Itqan's strongest offering). Use image backgrounds from real projects inside service cards.

### 3. Portfolio cards are data-heavy, not visual-enough
Current Itqan project cards show: category badge, title, subtitle, 3 tags, and a CTA link. This is a lot of metadata for what should be a visual-first experience. **Fix:** Make cards larger, image-dominant. Show title and one-line descriptor only. Remove tags from cards (they can live on the case study page).

### 4. Case study pages lack visual drama
Current structure: cover image > title > Behance link > challenge > approach > result > 3 mockups > testimonial. The challenge/approach/result structure is solid but the visual presentation is text-heavy in the top half. **Fix:** Open with a full-bleed hero image, then interleave copy blocks with large visual sections (process images, detail shots, before/after).

### 5. The "Brand Statement" section is redundant
The section between hero and social proof ("Where clarity becomes identity...") repeats the hero's message in different words. **Fix:** Remove it entirely. Let the hero do its job, then immediately prove it with social proof.

### 6. FAQ on the homepage is unusual for a premium agency
Neither won.agency nor comparable premium agencies (Pentagram, Collins, Ramotion) put FAQ on the homepage. It signals "people have questions about hiring us" rather than "hiring us is the obvious choice." **Fix:** Move FAQ to a standalone page or to the contact page only.

### 7. Budget dropdown signals low-end positioning
Starting at "$1,000-$5,000" tells premium clients this agency works with very small budgets. Won.agency's budget field is a dropdown but the ranges aren't visible in the audit. **Fix:** Start at "$5,000-$10,000" minimum, or use ranges like "Under $10K / $10K-$25K / $25K-$50K / $50K+".

## Technical readiness

### Can the current codebase support the rebuild?

**Yes, with minor refactoring.** The codebase is well-structured and does not require a rewrite.

**Strengths (keep as-is):**
- Clean Next.js 14 App Router architecture with proper server/client separation
- Well-organized component structure (30 components across 4 subdirectories)
- Centralized animation system in `src/lib/motion.ts` (168 lines, well-documented)
- Tailwind config correctly defines all brand colors and fonts
- TypeScript strict mode enabled throughout
- Minimal, focused dependencies (5 runtime, 7 dev)
- Image optimization configured (AVIF + WebP)
- Accessibility: `prefers-reduced-motion` respected in animations
- SEO: metadata, OG tags, JSON-LD schema, sitemap all present

**Issues to address before rebuild:**
1. **Unused component:** `AnimatedArrow.tsx` — delete it
2. **Hardcoded form IDs:** Formspree (`xlgpqnjl`) and Kit.com (`9240792`) IDs are hardcoded in components — move to env variables
3. **Hardcoded content in components:** FAQ data (7 items in `FAQ.tsx`), capabilities list (15 items in `services/page.tsx`) — move to `src/data/`
4. **API route is a stub:** `api/contact/route.ts` only does `console.log` — either remove or implement properly (Formspree handles submission directly)
5. **No .env file:** All integration IDs hardcoded. Create `.env.local` and `.env.example`
6. **No analytics:** No Google Analytics, Vercel Analytics, or any tracking. Must add before redesign so we can measure impact.
7. **No legal pages:** Missing Privacy Policy and Terms of Service (required for UAE business)
8. **Button styling duplication:** The same `inline-flex items-center gap-2 bg-brand-dark text-brand-cream px-* py-* rounded-full` pattern appears 15+ times — extract to a shared `Button` component
9. **BRAND.md does not exist** — should be created next session to document the brand system for future contributors

**Verdict:** The codebase can be iteratively rebuilt. No need to start from scratch. Each phase of the rebuild can ship as a PR against the existing architecture.

## Prioritized rebuild plan

### Phase 1: Copy & Structure Rewrite (Homepage)
**Goal:** Transform the homepage from a 10-section portfolio overview into a 6-section conversion machine.

**Scope:**
- Rewrite all homepage headlines and body copy (Hero, Services preview, Portfolio preview, CTA)
- Remove sections: Brand Statement, Process Steps, Benefits comparison, FAQ
- Restructure hero: new headline, new subhead, single CTA, scrolling project preview or full-bleed image
- Add a quantified social proof element (metric banner or client outcome stat)
- Tighten testimonial placement (inline with portfolio, not standalone)
- Increase section padding (80-120px vertical on desktop)

**Acceptance criteria:**
- [ ] Homepage has 6-7 sections maximum
- [ ] Every headline is outcome-oriented (no process descriptions)
- [ ] At least one quantified metric visible above the fold or in first scroll
- [ ] Lighthouse performance score remains 90+
- [ ] Mobile responsive, no layout regressions

**Estimated sessions:** 2-3

**Goal:** Make the work page and case studies sell outcomes, not just show mockups.

- Redesign project cards: larger, image-dominant, minimal metadata

- Restructure case study template: full-bleed hero > interleaved copy/visuals > result metrics > testimonial > next project CTA
- Add quantified results where possible (Nexilink investor competition win, etc.)
- Add filtering by category if project count reaches 6+

**Acceptance criteria:**
- [ ] Work page shows 6+ projects
- [ ] Each case study has at least one concrete result metric or milestone
- [ ] Case study hero is full-bleed with project imagery
- [ ] "Next project" navigation works at end of each study
- [ ] Visual variety between case studies (not identical layouts)

**Estimated sessions:** 2-3

### Phase 3: Services Page & Contact Page
**Goal:** Services page that builds authority; contact page that reduces friction.

**Scope:**
- Rewrite all service descriptions (outcome-first, not process-first)
- Integrate case study visuals within service sections
- Reduce service page density (remove 15-item capabilities list, or fold into individual services)
- Redesign contact form: fewer fields, aspirational headline, email alternative, response time promise
- Adjust budget ranges to signal premium positioning ($5K minimum)
- Extract shared Button component (technical debt cleanup)

**Acceptance criteria:**
- [ ] Each service has max 1 paragraph + 3-4 deliverables
- [ ] Contact form has 5 fields maximum
- [ ] Budget starts at $5,000+
- [ ] Email alternative visible on contact page
- [ ] Button component extracted and used across all pages

**Estimated sessions:** 1-2

### Phase 4: About Page, Footer, & Infrastructure
**Goal:** Build trust through team credibility and professional polish.

**Scope:**

## Risks

### 1. Copy ownership (validate with Bisma)
Rewriting all copy is the highest-impact change but also the most subjective. Bisma (Chief of Design) should review and approve all headline/subhead rewrites before implementation. Risk: multiple revision rounds if voice isn't aligned on first pass.

### 2. Portfolio depth
Itqan has only 4 case studies. The rebuild plan calls for 6+. If there aren't 2 more projects ready to showcase, the work page will still feel thin. **Mitigation:** Consider "mini-studies" — a single hero image + 3 sentences + key result — for projects that don't warrant a full case study.

### 3. Metric availability
The audit repeatedly calls for quantified results, but not all projects have clear metrics. **Mitigation:** Use qualitative milestones ("Won first place at [competition]", "Launched in 8 weeks", "Used by 3 departments") rather than forcing revenue/growth numbers that don't exist.

### 4. "With Itqan vs Without Itqan" removal pushback
The Benefits comparison section may have been added deliberately. Removing it is the right call for premium positioning, but validate that the team agrees before deleting it.

### 5. Budget range change impact on lead volume
Moving the minimum from $1,000 to $5,000 will filter out some leads. This is intentional (premium positioning) but could reduce initial inquiry volume. **Mitigation:** Monitor contact form submission rate for 2 weeks after launch. Can always adjust.

### 6. Analytics gap
There is currently zero analytics on the site. We cannot measure the impact of the redesign without a baseline. **Critical:** Add analytics in Phase 4 (or even earlier as a standalone quick fix) to establish baseline metrics before any visual changes go live.

### 7. SEO regression
Restructuring pages and rewriting copy can impact search rankings. **Mitigation:** Preserve existing URL structure. Don't change routes. Keep meta descriptions and OG tags updated for every page change.

### 8. No BRAND.md
The brand system is documented only in CLAUDE.md's project instructions. A standalone BRAND.md should be created before the rebuild so all contributors (human or AI) work from the same source of truth. Flagged for next session.
